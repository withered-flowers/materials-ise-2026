## 1. Panduan Cepat Alur Kerja GitHub Web (Tanpa CLI)

| Tindakan di GitHub Web | Tombol & Langkah Visual di Browser |
| :--- | :--- |
| **Mengunduh Starter Code** | Buka repositori template materi > Klik tombol hijau **`<> Code`** > Pilih **Download ZIP** > Ekstrak berkas di komputer lokal. |
| **Membuat Repositori Baru** | Buka [github.com](https://github.com) > Klik tombol **`+`** (atau tombol **New**) > Beri nama repositori > Pilih **Public** > Klik **Create repository**. |
| **Mengunggah Berkas Pertama Kali** | Di repositori baru yang kosong, klik tautan **uploading an existing file** > *Drag and drop* berkas `index.html`, `style.css`, dan `script.js`. |
| **Menyimpan Riwayat (Commit)** | Pada formulir **Commit changes**, ketik pesan ringkas > Pilih **Commit directly to the `main` branch** > Klik tombol hijau **Commit changes**. |
| **Mengunggah Berkas Tambahan** | Klik menu **Add file** > **Upload files** > Tarik berkas baru ke area browser > Tulis pesan commit > Klik **Commit changes**. |
| **Mengedit Kode Langsung di Web** | Klik nama berkas (misal `index.html`) > Klik ikon pensil (**Edit this file**) > Ubah kode di browser > Klik **Commit changes**. |

## 2. Panduan Alur Kerja Netlify Dashboard (Web UI)

Tanpa perlu menginstal Netlify CLI di terminal, seluruh pengelolaan situs dapat dilakukan secara visual melalui browser:

| Tindakan di Netlify Dashboard | Lokasi Menu & Langkah |
| :--- | :--- |
| **Menambahkan Proyek Baru** | Klik **Add new site** > **Import an existing project** > Pilih **GitHub** > Pilih repositori Anda. |
| **Konfigurasi Build Statis** | *Branch*: `main`, *Build command*: (kosongkan), *Publish directory*: (kosongkan / `.`). |
| **Mengubah Nama Subdomain** | Masuk ke situs > **Site configuration** > **General** > **Site details** > Klik **Change site name**. |
| **Memantau Status Deployment** | Buka tab **Deploys** untuk melihat riwayat rilis otomatis dari commit GitHub (*Published* atau *Building*). |
| **Melihat Log Rilis** | Klik pada salah satu riwayat deploy di tab **Deploys** untuk melihat log pemrosesan Netlify secara mendalam. |

## 3. Ambang Batas & Kategori Audit Google Lighthouse

### A. Rentang Skor Kategori

| Rentang Skor | Warna Indikator | Makna & Status Kualitas |
| :---: | :---: | :--- |
| **90 – 100** | Hijau | **Sangat Baik (Optimal)**: Memenuhi standar industri web modern. |
| **50 – 89** | Oranye | **Cukup Baik**: Berfungsi normal, namun masih ada peluang penghematan waktu muat. |
| **0 – 49** | Merah | **Perlu Perbaikan Segera**: Terdapat kendala performa atau aksesibilitas yang mendesak. |

### B. 5 Metrik Kunci Performa Google Lighthouse

| Indikator Metrik | Bobot Skor | Kategori Baik (Hijau) | Perlu Peningkatan (Oranye) | Kategori Buruk (Merah) |
| :--- | :---: | :--- | :--- | :--- |
| **First Contentful Paint (FCP)** | **10%** | ≤ 1,8 detik | 1,8 – 3,0 detik | > 3,0 detik |
| **Speed Index (SI)** | **10%** | ≤ 3,4 detik | 3,4 – 5,8 detik | > 5,8 detik |
| **Largest Contentful Paint (LCP)** | **25%** | ≤ 2,5 detik | 2,5 – 4,0 detik | > 4,0 detik |
| **Total Blocking Time (TBT)** | **30%** | ≤ 200 ms | 200 – 600 ms | > 600 ms |
| **Cumulative Layout Shift (CLS)** | **25%** | ≤ 0,1 | 0,1 – 0,25 | > 0,25 |

### C. Fokus Pemeriksaan 4 Kategori Audit

| Kategori Audit | Fokus Evaluasi Utama |
| :--- | :--- |
| **Performance** | Kecepatan pemuatan berkas, efisiensi script, dan kestabilan layout visual. |
| **Accessibility** | Kontras warna teks, atribut `alt` pada gambar, label formulir, dan tombol yang jelas. |
| **Best Practices** | Koneksi HTTPS penuh, bebas dari error di console browser, dan keamanan library. |
| **SEO** | Keberadaan tag `<title>`, `<meta name="description">`, meta viewport, dan link deskriptif. |

## 4. Matriks Penyelesaian Masalah (Troubleshooting)

### 1. Halaman Menampilkan "404 Page Not Found" di Netlify
- **Gejala**: Ketika membuka tautan URL situs Netlify, muncul halaman bertuliskan *Page Not Found*.
- **Penyebab**:
  1. Berkas HTML utama tidak bernama `index.html` (misalnya bernama `home.html` atau `Index.html`).
  2. Berkas `index.html` berada di dalam subfolder yang tidak terdaftar, bukan di akar repositori GitHub.
- **Solusi**:
  - Pastikan berkas utama bernama persis `index.html` (huruf kecil semua) dan berada tepat di akar repositori.

### 2. Tampilan CSS Tidak Muncul atau Script Tidak Berfungsi
- **Gejala**: Halaman web hanya berupa teks polos tanpa warna, tata letak berantakan, atau tombol tidak merespons.
- **Penyebab**: Tag HTML menggunakan jalur berkas absolut dari harddisk komputer pribadi (misalnya: `href="C:/Users/Dokumen/style.css"`).
- **Solusi**:
  - Ganti seluruh pemanggilan berkas menjadi jalur relatif sederhana, seperti `<link rel="stylesheet" href="style.css">` dan `<script src="script.js"></script>`.

### 3. Kendala Git: "fatal: remote origin already exists"
- **Gejala**: Muncul pesan error saat menjalankan `git remote add origin <URL>`.
- **Penyebab**: Repositori lokal sudah memiliki konfigurasi alamat remote dengan nama `origin`.
- **Solusi**:
  - Periksa alamat remote saat ini menggunakan `git remote -v`.
  - Jika ingin memperbarui ke alamat repository baru, jalankan:
    ```bash
    git remote set-url origin <URL_REPOSITORY_BARU>
    ```

### 4. Skor Google Lighthouse Rendah atau Berfluktuasi
- **Gejala**: Skor performa menunjukkan warna oranye atau merah padahal website statis berukuran kecil.
- **Penyebab**:
  1. Pengujian dilakukan di jendela browser biasa yang aktif dengan ekstensi pihak ketiga (adblocker, translator, dsb.).
  2. Gambar belum terkompresi atau tidak memiliki atribut `width` dan `height`.
- **Solusi**:
  - Selalu jalankan audit Lighthouse pada **Jendela Penyamaran (Incognito Window)** Google Chrome.
  - Kompres berkas gambar menjadi format WebP dan tambahkan atribut dimensi pada tag `<img>`.
